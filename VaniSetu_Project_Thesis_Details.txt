1. ABSTRACT & EXECUTIVE SUMMARY
====================================================================================================

Sign language is the primary medium of communication for millions of deaf and speech-impaired individuals 
worldwide. However, a significant communication barrier exists between signers and non-signers due to a 
widespread lack of sign language fluency in the general public.

VaniSetu is an end-to-end, enterprise-grade Artificial Intelligence application designed to bridge this gap. 
The system translates hand gestures into text and audible speech in real time (Sign-to-Text) and converts 
typed words or sentences back into sign language reference animations (Text-to-Sign). 

Key Technical Innovation:
Rather than relying on raw pixels which suffer from high computational overhead, sensitivity to background 
lighting, and skin-tone bias, VaniSetu extracts 63-dimensional wrist-normalized, scale-invariant 3D hand keypoints 
using Google MediaPipe. Feature sequences are processed through a two-stage Hybrid ML/DL architecture:
  1. A pre-trained CNN-LSTM network that extracts 128-dimensional spatio-temporal embeddings.
  2. A Random Forest ensemble head (300 estimators) trained on frozen embeddings for fast, CPU-friendly, 
     high-precision classification.

Additional Assistive Features:
  - Real-Time Web Speech Text-to-Speech (TTS) engine.
  - Automatic English-to-Hindi and English-to-Marathi multi-lingual translation.
  - Automated Emergency SMTP Email Alert System that dispatches immediate email notifications to 
    designated care-receivers (e.g., doxpro26@gmail.com, gaikwadgaurav685@gmail.com) upon detecting 
    emergency keywords (e.g., "ALERT", "HELP", "SOS", "EMERGENCY") or manual trigger.
  - Local LLM Integration (via Ollama) for conversational assistance without cloud reliance.

2.1 Problem Statement:

  - Implement a full-duplex translation system (Sign-to-Text and Text-to-Sign).
  - Integrate multi-lingual translation (Hindi/Marathi) and Text-to-Speech audio output.
  - Build an automated emergency SMTP dispatch system to notify emergency contacts.

4. MATHEMATICAL FORMULATION & DATA PREPROCESSING
====================================================================================================

4.1 3D Hand Keypoint Extraction:
MediaPipe detects 21 3D hand keypoints per frame:
  Keypoint P_i = (x_i, y_i, z_i),  for i = 0, 1, ..., 20.
  where i=0 corresponds to the Wrist landmark.

4.2 Wrist-Relative Translation & Scale Invariant Normalization:
To achieve translation and scale invariance regardless of hand distance from the camera:
  1. Translation Normalization (Wrist-relative):
     P'_i = P_i - P_0  ==>  P'_0 = (0, 0, 0)

  2. Scale Normalization:
     Let S = max_{i} ||P'_i||_2  (maximum Euclidean distance from wrist to any landmark).
     P''_i = P'_i / (S + 1e-6)

  3. Feature Vector Construction:
     Vector V in R^63 = [x''_0, y''_0, z''_0, x''_1, y''_1, z''_1, ..., x''_20, y''_20, z''_20]

4.3 Temporal Sliding-Window Sequence Construction:
Continuous video frames are grouped into temporal windows of size T = 30 frames with stride S = 5:
  Input Tensor Shape X_seq = (Batch_Size, 30, 63)
  Target Vector Y_seq = Class Label

For single static images, the single 63-D landmark vector is tiled T=30 times along the temporal axis, 
allowing static alphabets and motion gestures to share an identical model execution path.

5. MODEL DESIGN & TWO-STAGE TRAINING PIPELINE
====================================================================================================

5.1 Stage 1: Spatio-Temporal Feature Extractor (CNN-LSTM Backbone)
  - Input: (30, 63) temporal landmark sequence.
  - Conv1D Layer 1: 64 filters, kernel size 3, ReLU activation.
  - Conv1D Layer 2: 64 filters, kernel size 3, ReLU activation.
  - MaxPooling1D: pool size 2.
  - Spatial Dropout: 0.3 rate.
  - Bidirectional LSTM: 128 units (returns sequences).
  - LSTM Layer 2: 64 units (returns final temporal state).
  - Dense Bottleneck Layer: 128 units, Linear activation (Spatio-Temporal Embedding Vector E in R^128).
  - Softmax Classification Head: Pre-trained with Categorical Cross-Entropy Loss (Adam optimizer, LR=0.001).

5.2 Stage 2: Ensemble Random Forest Classifier Head
  - Rationale: Deep neural network dense outputs can overfit on limited dataset sizes. Random Forest heads 
    exhibit superior generalization, robust decision boundaries, and instant training execution.
  - Execution: The 128-D bottleneck embeddings E are extracted for all training samples with frozen backbone weights.
  - Classifier: RandomForestClassifier with 300 Decision Trees (`n_estimators=300`, `n_jobs=-1`).
  - Output: Final Sign Class Prediction + Class Probability Distribution.

5.3 Real-Time Majority-Vote Temporal Smoothing:
To eliminate frame-to-frame prediction flickering during live camera capture:
  Predictions across a sliding window of size N=5 frames are gathered:
  Final_Predicted_Label = Mode({Pred_{t-4}, Pred_{t-3}, Pred_{t-2}, Pred_{t-1}, Pred_t})

   - Description: Predicts sign label from base64 webcam frame or uploaded image.

   - Description: Converts typed text into character & custom sign reference cards.
   - Request Body: { "text": "HELLO" }
   - Response: { "sequence": [ { "char": "H", "sign_image": "/api/sign-image/H", ... } ] }

4. GET /api/smtp-config
   - Description: Fetches current SMTP configuration and recipient registry.

5. POST /api/smtp-config
   - Description: Updates SMTP host, port, TLS setting, sender email, and target recipients.

6. POST /api/send-alert
   - Description: Sends an immediate email alert via SMTP.
   - Request Body: { "text": "ALERT NEED ASSISTANCE", "recipient": "person1@gmail.com, person2@gmail.com" }
